# Реализация модели через Hibernate

## Что добавлено

`src/main/java/ru/vkr/materials/model` содержит 10 JPA-сущностей:

| Класс | Таблица |
|---|---|
| Unit | units |
| Category | categories |
| Material | materials |
| Department | departments |
| Warehouse | warehouses |
| Supplier | suppliers |
| User | users |
| MaterialBatch | material_batches |
| InventoryDocument | inventory_documents |
| InventoryDocumentItem | inventory_document_items |

Три перечисления задают роли, типы документов и статусы. Классы находятся под корневым пакетом приложения, поэтому Spring Boot обнаруживает их автоматически.
Hibernate уже подключен зависимостью spring-boot-starter-data-jpa. Используются аннотации jakarta.persistence.

## Как читать модель

- @Entity обозначает сущность, @Table задает имя таблицы.
- @Id и @GeneratedValue(IDENTITY) задают первичный ключ, генерируемый PostgreSQL.
- @Column явно задает имя и параметры колонки. Java-поле id сохраняется как id_<таблица>.
- @ManyToOne и @JoinColumn описывают FK: много материалов относятся к одной единице измерения. Это та же связь 1:N со стороны потомка.
- Связи с родителями загружаются LAZY. Работать с ними следует внутри транзакции сервисного слоя.
- InventoryDocument.items — обратная сторона @OneToMany(mappedBy = "document"). Добавление через addItem синхронизирует обе стороны. Сохранение документа сохраняет новые строки, каскадного удаления нет.
- Для остальных связей пока достаточно направления от потомка к родителю: коллекции всех дочерних записей не требуются для наличия связи 1:N в базе.
- Количество и цена — BigDecimal с четырьмя знаками после запятой. Срок годности — LocalDate, время проведения — Instant.
- Названия enum сохраняются текстом, а не порядковыми номерами.

Репозитории в пакете repository расширяют JpaRepository<Сущность, Long> и предоставляют сохранение и поиск. Это слой доступа к данным, а не готовые пользовательские операции выдачи.

## Миграция существующей базы

V1 не изменена. V2__implement_laboratory_model.sql будет автоматически применена при следующем запуске приложения.
Она создает справочники и документы, переименовывает materials.id в id_materials, переносит старую текстовую единицу в units и устанавливает FK. Существующие строки, их идентификаторы и created_at сохраняются. Старое ограничение уникальности кода удаляется согласно принятой модели без AK.

Старые материалы получают категорию «Без категории», признак активности true и has_expiry=false: из старой схемы невозможно определить наличие срока годности. Эти значения потребуется уточнить перед вводом партий.
Создаются один склад и согласованная структура подразделений. Склад не создается в departments. Пользователи, пароли и операции не заполняются демонстрационными данными.

ddl-auto остается validate: Flyway меняет структуру, Hibernate проверяет соответствие сущностям. При ошибке миграции нельзя редактировать уже примененную V1 или удалять историю Flyway.

## Что уже ограничено базой

PK и FK; обязательность полей; типы и статусы документов; положительное количество и номер строки; неотрицательная цена; допустимые стороны документа; наличие даты проведения для POSTED; запрет ссылки подразделения на само себя.

## Что будет в сервисном слое

Проведение с проверкой доступного остатка при конкурентной работе, запрет выдачи просроченной партии, обязательность срока годности по has_expiry, запрет циклов подразделений, запрет изменения проведенных документов, проверка наличия строк, запрет повторного оприходования учетной партии, права пользователей и хеширование реальных паролей. До появления этого слоя не следует создавать проведенные документы через репозиторий как готовую операцию учета.

Альтернативные ключи в новой модели не создаются. Перед реализацией авторизации отдельно потребуется решить однозначную идентификацию пользователя по логину.

## Проверка

`./scripts/test-model.sh` требует работающий PostgreSQL на 5433. Скрипт создает отдельную временную базу, разворачивает старую таблицу с контрольной записью, применяет V2 и запускает четыре интеграционных теста Spring Boot/Hibernate. После завершения база удаляется. Рабочая medical_materials не изменяется. Baseline V1 включен только для этой временной фикстуры.

Тесты проверяют сохранность старой записи и единицы измерения, сохранение и чтение поступления/выдачи с общей партией, связи подразделений, дробные значения, запрет выдачи без получателя и отрицательной цены. Проходящий тест не означает, что проведение документов уже реализовано.

Обычная сборка: `./scripts/build.sh`. Интеграционные тесты запускаются отдельно, так как им требуется PostgreSQL.

## Следующий запуск

Остановить старое приложение (Ctrl+C), выполнить `./scripts/run.sh`. В выводе появится применение миграции V2 и запуск Hibernate с проверкой 10 таблиц. Обновить дерево подключения в DBeaver. Главная страница и /api/info сохраняются.
